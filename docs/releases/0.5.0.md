# ConfigOps 0.5.0

Released 2026-08-24. This release expands safe site-setting undo beyond the plugins for which ConfigOps ships a dedicated adapter.

## Smart Undo beyond adapters

- A site administrator can explicitly enable **Smart undo for ordinary settings arrays** under **ConfigOps → Plugin support**.
- For an unclaimed associative `wp_options` update, ConfigOps verifies every addition, removal, and replacement against the captured before and after snapshots.
- Before writing, it rechecks current adapter ownership, current parent structure, every target value, and the option's autoload mode.
- Unrelated keys added or changed later are preserved. One conflicting target refuses the complete patch.
- A failed or synchronously rewritten write is compensated back to the complete current state and audited distinctly.

## Network operations

- Network Admin now supports named Network Change Sessions for planned work spanning several requests.
- The active-session pointer is network-owned and atomic, and start, stop, authorization, finalization, and cleanup follow the same fail-closed ownership rules as site sessions.
- Named sessions group Network Options evidence without enabling whole-network-change undo. Complete additions and updates remain mutation-level only.

## Deliberate boundary

Smart Undo is structural, not semantic, and remains opt-in. It does not restore custom tables, direct SQL, secrets, roots, list indexes, integer-keyed parents, truncated evidence, adapter-owned options, or a target that changed again. ConfigOps is still a compensating settings-undo layer, not a database snapshot or transactional rollback engine.
